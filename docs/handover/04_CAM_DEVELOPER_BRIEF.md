## 2. 축 규약 — 좌표를 보내기 전에 필독

**단위와 부호가 축마다 다릅니다. 틀려도 에러가 나지 않고, 와이어가 반대로 굽습니다.**

| 축 | ID | 단위 | + 방향 | 기준점 | steps/unit | 캘리브레이션 |
|---|---|---|---|---|---|---|
| FEED | 0 | ° | 시계방향 | **없음(센서 미장착)** | 200 | ⚠ **미검증 자리표시자** |
| BEND | 1 | ° | 시계방향 | 리밋 디스크 | 23.0167 | ✅ 실측 |
| ROTATE | 2 | ° | — | — | — | 미장착 |
| LIFT | 3 | **mm** | **아래** | 최상단 스위치 = 0 | 200 | ✅ 실측 |

### ⛔ LIFT 부호
**`+`가 아래**입니다. 0이 최상단 스위치이고 스트로크는 **+230 mm**(최하단)까지입니다.
CAM 모델이 `+Z`를 위로 잡고 있으면 캐리지를 반대쪽 끝단으로 밀어붙입니다.

### ⚠ FEED는 캘리브레이션되지 않았습니다
`200 steps/deg`는 검증되지 않은 자리표시자이고, 리밋 센서가 없어 **홈잉이 불가능**합니다
(`/api/motor/home` 이 `MOTOR_HOME_ERROR` 반환). 마킹 기준 1회전 실측 전까지 FEED는
**상대 이동으로만** 쓰세요. 절대 피드 길이를 이 값 위에 쌓지 마십시오.

**착지 정확도**(재홈잉 후 실측): BEND ≤ 0.21°, LIFT 0.00 mm.
가감속은 **지정 좌표 안에서 완결**됩니다 — 45°를 지령하면 45°를 지나치지 않습니다.

## 3. 통합 방식 3가지

일을 해결하는 **가장 높은 수준**을 고르세요. 레이어가 아니라 각각 완결된 경로입니다.

- **A · 3D 곡선 → 굽힘 프로그램** — `POST /api/cam/generate` 에 점열을 보내면 재질별
  스프링백 보정이 적용된 B-code를 돌려줍니다. 프리뷰는 모터를 움직이지 않으므로
  **실행 전에 형상을 검증**하세요.
- **B · B-code 직접 실행** — CAM이 이미 feed/rotate/bend 3요소를 뽑는다면
  `POST /api/bending/execute`, 진행률은 `GET /api/bending/status`.
- **C · 축 직접 제어** — 교정·티칭·治具 세팅용. `move_to`(절대) / `move`(상대) / `jog`(수동).

**장비 없이 개발**: 목(mock) 백엔드가 동일한 envelope·필드·에러코드를 반환합니다.
노트북에서 클라이언트를 완성한 뒤 벤치를 만지세요 (`03_MOCK_MODE.md`).

## 4. 클라이언트가 지켜야 할 인터록

빨리 물리는 순서대로 정렬했습니다.

1. **홈잉은 비동기입니다.** `POST /api/motor/home` 은 즉시 반환합니다.
   `GET /api/motor/limits` 의 `homing` 이 false가 될 때까지 폴링하고 `error` 가 null인지
   확인하세요. **진행 중 다른 모션을 걸면 홈잉이 취소됩니다.**
2. **한 번에 한 축만 움직입니다.** 3개 드라이버가 STEP 신호선 하나를 공유합니다.
   연속된 `move_to` 는 서로 취소하지 않고 **대기열에 쌓여 순서대로** 실행되며, 각 요청은
   자기 차례가 끝날 때 응답합니다. 대기 수는 `/limits` 의 `queued`.
3. **E-STOP 감시.** `state == 6` 이면 모든 모션이 거부됩니다. UI를 잠그고, 조작자가
   상황 해소를 확인한 뒤에만 `POST /api/motor/reset`.
4. **드라이버 폴트는 `reset`으로 복구, `enable` 아닙니다.** 이동이
   `fault detected (0x00810)` 로 거부되면 단락 검출이 **래치**된 상태입니다.
   `POST /api/motor/reset` 이 전원 차단 없이 해제하며 `fault_clear.still_faulted` 가
   비어 있으면 완료입니다. `/api/motor/enable`·`/disable` 은 M7 코프로세서로 가므로
   **벤치 칩에 닿지 않습니다.**
5. **세 축이 똑같이 폴트나면 전원 문제입니다.** 폴트 워드가 비트 단위로 동일하고
   `stst` 가 꺼져 있으면 공유 12 V 레일 문제이지 모터 3개 고장이 아닙니다.
   축을 하나씩 시험하지 말고 드라이버 단자에서 VMot를 측정하세요.
6. **정밀 작업 전 재홈잉.** 전원이 꺼진 동안 축이 손으로 움직였을 수 있고,
   카운터는 개루프입니다.
7. **에러도 HTTP 200으로 옵니다.** `success` 를 확인하고 `code` 를 읽으세요.
   5xx는 서버 자체 장애입니다.

## 5. 속도와 토크

### 속도 상한은 설정이 아니라 유도값

STEP 하드 클램프 8000 Hz ÷ 축 캘리브레이션. 초과 요청은 잘립니다.
올리려면 마이크로스텝이나 기구비를 바꿔야 하고, API로는 불가능합니다.

| 축 | 상한 | 유도 |
|---|---|---|
| BEND | 347.6 °/s | `8000 / 23.0167` |
| FEED | 40 °/s | `8000 / 200` |
| LIFT | 40 mm/s | `8000 / 200` |

가감속은 축별·영속: `PUT /api/motor/profiles/{axis}` —
`accel`/`decel` 물리 단위 1–200, `shape` 는 `linear` | `scurve`.
S커브는 **설정한 가속도를 초과하지 않으면서** 부드럽게만 만듭니다.

### 토크는 축별, 두 가지가 독립

```bash
curl -X PUT http://192.168.77.2:8000/api/motor/protection \
     -H 'Content-Type: application/json' \
     -d '{"axes": {"1": {"run_cs": 14}, "0": {"run_cs": 5}}}'
```

| 필드 | 뜻 | 범위 |
|---|---|---|
| `run_cs` | 축이 **움직일 때**의 코일 전류 | 1–19 |
| `hold_cs` | 정지 중 위치 유지 전류 | 1–19 |
| `run_cs_effective` | **실제로 코일에 들어가는 값**(PSU 캡 적용 후) | 응답 전용 |

**보낸 값이 아니라 `run_cs_effective` 를 읽으세요.** PSU 캡을 넘는 요청은 거부가 아니라
깎이므로, 공급기가 허용하는 것보다 크게 요청하면 두 값이 달라집니다.

### ⛔ 하드웨어 상한 — 우회 불가

전류 스케일 상한은 **19**입니다. 2026-05-08에 CS=31로 드라이버 보드 2장이 소손됐습니다.
1–19 밖은 `422`로 거부되고, 클램프가 **라우터 → 서비스 → 레지스터 쓰기 직전** 3중으로
재적용되므로 저장 파일을 손으로 고쳐도 올릴 수 없습니다.
이 경로들을 실제로 뚫어보는 테스트 12개가 상시 돌고 있습니다.

## 6. 거짓말하는 표시들

측정값처럼 보이지만 아닙니다. 전부 실제로 진단 시간을 잡아먹었던 것들입니다.

| 표시 | 실제 |
|---|---|
| `signals.vmot` | 전압 측정이 아니라 **"칩이 SPI에 응답함"** 추론값. 로직은 VCC_IO로 돌아서 12 V가 완전히 없어도 `true` 로 남습니다. **전원 확인에 쓰지 마세요.** |
| `drv_status` | 벤치 백엔드에서 **`0` 고정**. 진짜 칩별 폴트 플래그는 `/ws/motor/diag` 구독 — `ot`/`otpw`/`s2ga`/`s2gb`/`ola`/`olb`/`stst` 를 드라이버별로 방송합니다. |
| 레지스터 덤프 | TMC260C 레지스터는 **쓰기 전용**. 덤프는 드라이버가 마지막으로 쓴 그림자 값이지 칩 상태가 아닙니다. 관련: TMC260C에 `GET /api/motor/diag/register/…` 를 **호출하지 마세요** — 읽기가 0을 쓰는 것으로 구현돼 있습니다. |
| `sg_result` / `signals.sg_value` | StallGuard 부하 0–1023, **축이 회전 중일 때만** 의미가 있습니다. 정지·비여자 축의 값은 무의미합니다. 낮을수록 고부하이고, 트립은 고장이 아니라 부하 측정값이라 부하가 줄면 스스로 사라집니다. |

## 7. 알려진 제약

- **동시 다축 모션 불가.** 하드웨어 PWM STEP 라인 하나를 3개 드라이버가 공유해 이동이
  직렬화됩니다. 진짜 협조 제어는 배선 분리 + 디바이스트리 핀먹스 변경이 필요하며,
  경로는 문서화돼 있으나 구현되지 않았습니다.
- **FEED 미캘리브레이션·홈잉 불가.** 리밋 센서 없음, steps/deg는 자리표시자.
- **StallGuard는 무부하에서만 튜닝됨.** BEND가 `SGT +8`에서 사용 가능 구간(90 °/s
  무부하 208–512)이지만, **실제 와이어를 굽힐 때** 어디까지 떨어지는지는 미측정입니다.
  스톨 기반 홈잉 중단은 그때까지 비활성입니다.
- **래치 폴트 복구는 정상 벤치에서만 검증됨.** 해제 시퀀스가 무해하고 모든 칩을 깨끗하게
  되돌리는 것은 확인했지만, 진짜 래치된 폴트를 푸는 것은 재현하지 못했습니다
  (재현하려면 축을 하드스톱에 밀어넣어야 함).

## 9. 에러 코드

모든 에러는 **HTTP 200 + `success:false`** 로 옵니다.

| code | 의미 | 대응 |
|---|---|---|
| `CAM_INVALID_INPUT` | 점열·파라미터 범위 오류 | 입력 검증 |
| `CAM_INTERNAL_ERROR` | 변환 실패 | 로그 확인 후 재시도 |
| `BENDING_BUSY` | 이미 벤딩 실행 중 | `/api/bending/status` 확인 후 대기 |
| `MOTOR_HOME_ERROR` | 센서 없는 축 홈잉 / 센서 이상 | 축 번호·배선 확인 (FEED는 홈잉 불가) |
| `MOTOR_MOVE_ERROR` | 이동 실패(범위·E-STOP·드라이버 폴트) | `error` 문구 확인, `0x00810`이면 §4-4 |
| `MOTOR_BUSY` | 모션 중 드라이버 비활성화 시도 | `/stop` 후 재시도 |
| `MOTOR_PROTECTION_ERROR` | 보호·토크 설정 오류 | 파라미터 범위 확인 |
| `MOTOR_SG_ERROR` | StallGuard 설정 오류 | `sgt` 범위(−64~63) 확인 |
| `CAMERA_OFFLINE` | 카메라 세션 off | `/api/camera/connect` |
