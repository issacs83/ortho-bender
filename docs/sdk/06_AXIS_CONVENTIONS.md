# 축 규약 (Axis Conventions) — 좌표를 쓰기 전에 반드시 읽으세요

외부 애플리케이션(CAD/CAM 등)이 이 장비를 제어할 때 **가장 먼저 필요한 문서**입니다.
축마다 단위·부호·기준점이 다르므로, 이 표를 모르면 좌표를 잘못 보내게 됩니다.

모든 값은 2026-08-16 벤치에서 **센서 기준 실측**으로 확정했습니다.

---

## 1. 축 요약표

| axis | 이름 | 종류 | 단위 | 캘리브레이션 | `+` 방향 | 홈(원점) |
|:----:|------|------|:----:|--------------|----------|----------|
| 0 | FEED | 와이어 이송 (롤러 회전) | **mm** | 25.4648 steps/mm **(잠정값)** | 이송 방향 | 센서 없음 → `/zero` 수동 |
| 1 | BEND | 회전 (벤딩 다이, 연속) | **deg** | **23.0167 steps/deg** (1회전 = 8,286 steps) | 시계방향 | 리밋 센서(1개/회전) |
| 2 | ROTATE | 회전 | deg | — | 시계방향 | **벤치 미장착** |
| 3 | LIFT | 직선 (수직, T8 리드스크류 8 mm/rev) | **mm** | **200 steps/mm** (스트로크 230 mm) | **아래(하강)** | 최상단 리밋 센서 = 0 |

> ⚠️ **FEED와 LIFT가 mm**, BEND·ROTATE가 degree 입니다. FEED는 롤러가 회전하지만
> 지령 단위는 **나온 와이어 길이(mm)** 입니다 — CAM이 다루는 값이 그것이기 때문입니다.
> ⚠️ **LIFT의 `+` 는 아래쪽**입니다. 홈(최상단)이 0이고 바닥이 **+230 mm** 입니다.

### 이동 한계 (서버가 강제)

| axis | 1회 명령당 거리 상한 | 속도 상한 | 산출 근거 |
|:----:|---------------------|-----------|-----------|
| 0 FEED | 200 mm | **314.2 mm/s** | 8000 Hz ÷ 25.4648 steps/mm |
| 1 BEND | 360 deg | **347.6 deg/s** | 8000 Hz ÷ 23.0167 steps/deg |
| 3 LIFT | 240 mm | **40 mm/s** | 8000 Hz ÷ 200 steps/mm |

속도 상한은 **하드웨어 STEP 상한 8 kHz를 축 캘리브레이션으로 나눈 값**이며,
`GET /api/motor/calibration` 의 `speed_limit` 에서 항상 최신 값을 읽을 수 있습니다.
축마다 steps/unit이 다르므로 같은 숫자라도 실제 주파수가 다릅니다 — 캘리브레이션을
바꾸면 상한도 자동으로 따라갑니다.

상한을 넘는 값은 **조용히 잘리지 않고** `/api/motor/move_to` 가 자동으로 분할 실행해
목표에 도달합니다. (`/api/motor/move` 는 1회 명령이라 상한에서 잘립니다.)

## 2. 상대 이동 vs 절대 이동 — 가장 흔한 실수

| 엔드포인트 | 의미 | 예 |
|---|---|---|
| `POST /api/motor/move` | **상대**: 현재 위치에서 `distance` 만큼 | 현재 40°에서 `distance:45` → 85° |
| `POST /api/motor/move_to` | **절대**: `position` 좌표로 이동 | 현재 40°에서 `position:45` → 45° |

CAD/CAM 좌표를 그대로 보내려면 **`move_to` 를 쓰세요.**

---

## 3. 원점(홈) 잡는 법

정밀 작업 전에는 반드시 홈을 잡아 기준을 확정합니다.

```bash
# 리밋 센서가 있는 축(BEND=0x02, LIFT=0x08). 0 = 장착된 축 전체
curl -X POST http://<ip>:8000/api/motor/home -d '{"axis_mask":0}'
# 즉시 반환(state=HOMING) → 완료는 GET /api/motor/limits 의 homing:false 로 확인
```

- 홈 완료 후 그 지점이 **0**이 됩니다(센서 감지점 기준).
- FEED는 센서가 없으므로, 기계적 기준에 맞춘 뒤 `POST /api/motor/zero {axis:0}` 로 0을 선언합니다.
- 전원을 껐다 켜도 위치는 보존되지만(카운터 영속), **전원이 꺼진 동안 축을 손으로 움직였다면
  값이 어긋납니다.** 이 경우 다시 홈을 잡으세요.

## 4. 정밀도 (실측)

| 항목 | 값 |
|---|---|
| 지정 위치 착지 오차 | BEND ≤ 0.24° / LIFT 0.00 mm (1~180° · 1~200 mm, 30~300 deg/s 전 구간) |
| BEND 1회전 재현성 | 360.00° (편차 0.06%) |
| 최소 분해능 | BEND 0.043°/step, LIFT 0.005 mm/step |

가감속(사다리꼴·S-curve)은 **지정 위치 안에서 완결**됩니다. 즉 45°를 지령하면 45°에서
감속을 마치고 정지하며, 45°를 지나쳐서 멈추지 않습니다.

## 5. 안전 동작 (외부 앱이 알아야 할 것)

| 기능 | 동작 | 제어 |
|---|---|---|
| **E-STOP** | PWM 즉시 차단 + 전 축 초퍼 정지. 이후 모든 모션 명령 거부 | `POST /estop` → 해제는 `POST /reset` |
| **리밋 가드** | 이동 중 리밋 창에 진입하면 감속 정지 (LIFT에 적용) | `PUT /protection {limit_stop}` |
| **정지 토크** | **축별로** 유휴 시 코일 통전 유지(LIFT 중력 침하·FEED 외력 방지). 통전 중 초퍼 소음은 정상 | `PUT /protection {axes:{0:{hold_enabled,hold_cs}}}` |
| **모션 직렬화** | 조그·정지는 진행 중 모션을 즉시 대체(마지막 명령 우선). **절대 이동(`move_to`)은 취소하지 않고 대기열에 쌓여 순차 실행** | 자동 |

E-STOP 상태에서는 모든 모션 API가 `MOTOR_ESTOP` 계열 에러를 반환합니다.
외부 앱은 `GET /api/motor/status` 의 `state == 6 (ESTOP)` 을 감시하세요.

## 6. 동시 다축 이동에 대하여

**현재 벤치는 한 번에 한 축만 독립 제어할 수 있습니다.** STEP 신호선(PWM4) 1개와
DIR 1개를 3개 드라이버 보드가 **병렬로 공유**하고, 축 선택은 SPI로 초퍼를 켜고 끄는
방식이기 때문입니다.

| 방식 | 지원 | 설명 |
|---|:---:|---|
| 절대 이동 여러 축 연속 지시 | ✅ | `move_to` 는 **대기열에 쌓여 순차 실행**됩니다(서로 취소하지 않음). `GET /limits` 의 `queued` 로 대기 수를 볼 수 있습니다 |
| 여러 축 **락스텝** 동시 구동 | ✅ | 같은 속도·같은 방향으로 함께 움직이는 경우에 한해 가능(백엔드 `pulse_step_multi`) |
| 축마다 **다른 속도·거리로 동시** 이동 | ❌ | 배선 구조상 불가 — 아래 참조 |

**향후 확장 경로(하드웨어 확인 완료)**: i.MX8MP의 PWM2·PWM3·PWM4를 J21 핀 38·40·32에
각각 배치할 수 있고 DIR용 여유 핀(35·10)도 있습니다. 즉 **새 보드 없이 배선 분리 +
DTB 핀먹스 + 백엔드 다축 엔진**으로 진짜 동시·보간 이동이 가능합니다.
(PWM2는 현재 LVDS 백라이트가 점유 — 패널 미사용 시 해제 가능)

⚠️ 동시 실행을 임의로 흉내 내지 마세요: 두 모션이 같은 PWM과 위치 카운터를 덮어써서
좌표가 깨진 사례가 있습니다(그래서 서버가 직렬화합니다).

## 7. 운영 주의사항

- **BEND 저속 구간**: 아주 낮은 속도(수백 Hz 이하)에서는 모터 공진으로 스텝이 유실될 수 있습니다.
  정밀 이동은 **60 deg/s 이상**을 권장합니다(60·120·300 deg/s에서 1회전 오차 0 실측).
- **FEED 캘리브레이션 미완**: 현재 25.4648 steps/mm는 **잠정값**입니다. 롤러 직경을 아무도
  실측하지 않았고, 이 값은 `1600 steps/rev ÷ (π × 20 mm)` 로 계산한 것입니다.
  1600은 확정값입니다(1/16 마이크로스텝 + DEDGE → PWM 1사이클당 2 마이크로스텝,
  LIFT의 200 steps/mm 가 같은 근거로 검증됨). 롤러 직경만 미확정입니다.

  **한 번의 측정으로 확정됩니다** — 와이어에 표시하고 지령한 뒤 실제 나온 길이를 재면 됩니다:
  ```bash
  python3 tools/calibrate-feed.py --base http://<ip>:8000 --mm 100
  ```
  보정식은 `새 steps/mm = 기존 × (지령 mm ÷ 실측 mm)` 이고, 스크립트가
  `POST /api/motor/calibration` 으로 보드에 기록합니다.

  **분해능 주의**: 잠정값 기준 1스텝 = **0.039 mm** 이므로 0.1 mm 지령은 2~3스텝입니다.
  짧은 이동 오차가 최대 1스텝이므로 0.1 mm에 대해 **±0.04 mm** 가 남습니다.
  0.1 mm를 안정적으로 쓰려면 FEED의 마이크로스텝을 높이거나(현재 1/16) 롤러를 줄여
  steps/mm를 4배 이상 올려야 합니다. 실측 이전 기존 서술:

- (구) 실제 와이어 이송량이
  중요하다면 1회전 실측 후 `POST /api/motor/calibration` 으로 보정하세요.
- **ROTATE 축 미장착**: 벤치에는 FEED/BEND/LIFT 3축만 있습니다. B-code의 `beta_deg`(와이어 회전)는
  현재 벤치에서 실행되지 않습니다.

## 8. 캘리브레이션 변경

```bash
# 조회
curl http://<ip>:8000/api/motor/calibration
# 변경 (steps per unit) — 보드에 영속 저장됨
curl -X POST http://<ip>:8000/api/motor/calibration \
     -H 'Content-Type: application/json' \
     -d '{"axis":1,"steps_per_unit":23.0167}'
```

측정 방법(BEND 기준): 리밋 센서를 지나가도록 **저속(자기시동 영역, 200~300 Hz)** 으로 연속
회전시키며 센서 통과 지점 2회를 기록 → 그 간격이 1회전의 스텝 수입니다. 고속에서는 스텝
유실이 섞이므로 저속으로 측정하세요.
