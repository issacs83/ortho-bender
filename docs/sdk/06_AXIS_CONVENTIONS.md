# 축 규약 (Axis Conventions) — 좌표를 쓰기 전에 반드시 읽으세요

외부 애플리케이션(CAD/CAM 등)이 이 장비를 제어할 때 **가장 먼저 필요한 문서**입니다.
축마다 단위·부호·기준점이 다르므로, 이 표를 모르면 좌표를 잘못 보내게 됩니다.

모든 값은 2026-08-16 벤치에서 **센서 기준 실측**으로 확정했습니다.

---

## 1. 축 요약표

| axis | 이름 | 종류 | 단위 | 캘리브레이션 | `+` 방향 | 홈(원점) |
|:----:|------|------|:----:|--------------|----------|----------|
| 0 | FEED | 회전 (와이어 피드 롤러) | **deg** | 200 steps/deg **(미검증 기본값)** | 시계방향 | 센서 없음 → `/zero` 수동 |
| 1 | BEND | 회전 (벤딩 다이, 연속) | **deg** | **23.0167 steps/deg** (1회전 = 8,286 steps) | 시계방향 | 리밋 센서(1개/회전) |
| 2 | ROTATE | 회전 | deg | — | 시계방향 | **벤치 미장착** |
| 3 | LIFT | 직선 (수직, T8 리드스크류 8 mm/rev) | **mm** | **200 steps/mm** (스트로크 230 mm) | **아래(하강)** | 최상단 리밋 센서 = 0 |

> ⚠️ **LIFT만 직선축(mm)** 입니다. FEED는 이름과 달리 롤러 회전축이라 **degree** 로 지령합니다.
> ⚠️ **LIFT의 `+` 는 아래쪽**입니다. 홈(최상단)이 0이고 바닥이 **+230 mm** 입니다.

### 이동 한계 (서버가 강제)

| axis | 1회 명령당 거리 상한 | 속도 상한 | 비고 |
|:----:|---------------------|-----------|------|
| 0 FEED | 360 deg | 40 deg/s | |
| 1 BEND | 360 deg | 360 deg/s | 실제 상한은 STEP 8 kHz 클램프 |
| 3 LIFT | 240 mm | 40 mm/s | 스트로크 230 mm |

상한을 넘는 값은 **조용히 잘리지 않고** `/api/motor/move_to` 가 자동으로 분할 실행해
목표에 도달합니다. (`/api/motor/move` 는 1회 명령이라 상한에서 잘립니다.)

## 2. 상대 이동 vs 절대 이동 — 가장 흔한 실수

| 엔드포인트 | 의미 | 예 |
|---|---|---|
| `POST /api/motor/move` | **상대**: 현재 위치에서 `distance` 만큼 | 현재 40°에서 `distance:45` → 85° |
| `POST /api/motor/move_to` | **절대**: `position` 좌표로 이동 | 현재 40°에서 `position:45` → 45° |

CAD/CAM 좌표를 그대로 보내려면 **`move_to` 를 쓰세요.**

---

## 3. 원점(홈) 잡는 법

정밀 작업 전에는 반드시 홈을 잡아 기준을 확정합니다.

```bash
# 리밋 센서가 있는 축(BEND=0x02, LIFT=0x08). 0 = 장착된 축 전체
curl -X POST http://<ip>:8000/api/motor/home -d '{"axis_mask":0}'
# 즉시 반환(state=HOMING) → 완료는 GET /api/motor/limits 의 homing:false 로 확인
```

- 홈 완료 후 그 지점이 **0**이 됩니다(센서 감지점 기준).
- FEED는 센서가 없으므로, 기계적 기준에 맞춘 뒤 `POST /api/motor/zero {axis:0}` 로 0을 선언합니다.
- 전원을 껐다 켜도 위치는 보존되지만(카운터 영속), **전원이 꺼진 동안 축을 손으로 움직였다면
  값이 어긋납니다.** 이 경우 다시 홈을 잡으세요.

## 4. 정밀도 (실측)

| 항목 | 값 |
|---|---|
| 지정 위치 착지 오차 | BEND ≤ 0.24° / LIFT 0.00 mm (1~180° · 1~200 mm, 30~300 deg/s 전 구간) |
| BEND 1회전 재현성 | 360.00° (편차 0.06%) |
| 최소 분해능 | BEND 0.043°/step, LIFT 0.005 mm/step |

가감속(사다리꼴·S-curve)은 **지정 위치 안에서 완결**됩니다. 즉 45°를 지령하면 45°에서
감속을 마치고 정지하며, 45°를 지나쳐서 멈추지 않습니다.

## 5. 안전 동작 (외부 앱이 알아야 할 것)

| 기능 | 동작 | 제어 |
|---|---|---|
| **E-STOP** | PWM 즉시 차단 + 전 축 초퍼 정지. 이후 모든 모션 명령 거부 | `POST /estop` → 해제는 `POST /reset` |
| **리밋 가드** | 이동 중 리밋 창에 진입하면 감속 정지 (LIFT에 적용) | `PUT /protection {limit_stop}` |
| **정지 토크** | LIFT는 유휴 시 코일 통전 유지(중력 침하 방지). 통전 중 초퍼 소음은 정상 | `PUT /protection {hold_enabled, hold_cs}` |
| **모션 직렬화** | 새 모션 명령은 진행 중인 모션을 감속 취소하고 대체(마지막 명령 우선) | 자동 |

E-STOP 상태에서는 모든 모션 API가 `MOTOR_ESTOP` 계열 에러를 반환합니다.
외부 앱은 `GET /api/motor/status` 의 `state == 6 (ESTOP)` 을 감시하세요.

## 6. 운영 주의사항

- **BEND 저속 구간**: 아주 낮은 속도(수백 Hz 이하)에서는 모터 공진으로 스텝이 유실될 수 있습니다.
  정밀 이동은 **60 deg/s 이상**을 권장합니다(60·120·300 deg/s에서 1회전 오차 0 실측).
- **FEED 캘리브레이션 미완**: 현재 200 steps/deg는 플레이스홀더입니다. 실제 와이어 이송량이
  중요하다면 1회전 실측 후 `POST /api/motor/calibration` 으로 보정하세요.
- **ROTATE 축 미장착**: 벤치에는 FEED/BEND/LIFT 3축만 있습니다. B-code의 `beta_deg`(와이어 회전)는
  현재 벤치에서 실행되지 않습니다.

## 7. 캘리브레이션 변경

```bash
# 조회
curl http://<ip>:8000/api/motor/calibration
# 변경 (steps per unit) — 보드에 영속 저장됨
curl -X POST http://<ip>:8000/api/motor/calibration \
     -H 'Content-Type: application/json' \
     -d '{"axis":1,"steps_per_unit":23.0167}'
```

측정 방법(BEND 기준): 리밋 센서를 지나가도록 **저속(자기시동 영역, 200~300 Hz)** 으로 연속
회전시키며 센서 통과 지점 2회를 기록 → 그 간격이 1회전의 스텝 수입니다. 고속에서는 스텝
유실이 섞이므로 저속으로 측정하세요.
